# Ava-Vault submissions

Keep ADMIN_PASSWORD (shared staff password), OWNER_PASSWORD (distinct owner password), SESSION_SECRET (long random secret), and existing database configuration on the server. Create a separate PRIVATE GitHub repository, initialise it with a README, and set SUBMISSIONS_REPO=owner/repo and SUBMISSIONS_TOKEN to a fine-grained token with Contents read/write access to that repository. Never use the public avatar database repository for submissions. Configure hosting-level rate limits or a verified CAPTCHA for POST /api/submissions before public launch; the honeypot alone is not abuse protection. Queue supports up to 200 files; archive reviewed files periodically. Quick Import remains manual so existing privacy and validation checks are preserved. Test staff and owner permissions and imports in staging.
